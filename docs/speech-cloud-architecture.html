Architecture report / speech system

Real cloud transcription: OpenAI + OpenRouter

Selah display Branch: feat/speech-cloud-openai Status: staged, open PR

01 / Outcome

Cloud mode now sends live sermon audio to either OpenAI or OpenRouter and returns a real transcript under the same engine contract as the local drivers. The renderer still captures PCM and streams it over loopback WebSocket; the forked engine encodes buffered frames into a 16 kHz WAV and either POSTs multipart to OpenAI Audio Transcriptions (whisper-1) or POSTs base64 input_audio to OpenRouter's documented Responses API with a Google Gemini model. Provider text is parsed into a contract-valid final segment with session-relative timestamps. There is no local-engine fallback and no fake label: provider, model, per-provider key, consent, and Production Mode are validated in main before any fork, while failures refuse with actionable codes rather than starting whisper under a cloud name.

03 / Openrouter lane

OpenRouter is OpenAI-compatible in authentication, but audio input is not the /v1/audio/transcriptions endpoint. The documented route is the Responses API. This implementation follows OpenRouter's audio guide and Responses API reference; no model id was invented.

04 / Ins and outs

Local side

  • Renderer captures 16 kHz mono Int16 PCM and streams frames over the existing loopback WebSocket with the per-launch token.
  • The engine buffers a segment until the transport's silence endpointing, then prepends a canonical 44-byte RIFF/WAVE header using framesToWav().
  • Session state and elapsed milliseconds are local; one segment produces one final message with no word timestamps.

Remote side

  • OpenAI lane: POST https://api.openai.com/v1/audio/transcriptions with multipart model + file, JSON text response.
  • OpenRouter lane: POST https://openrouter.ai/api/v1/responses with JSON input_audio base64 WAV; transcript comes from output[].content[] output_text.
  • Both use Authorization: Bearer <provider key> and a 120-second abort timeout. Default models are whisper-1 and google/gemini-2.5-flash.

05 / Key and consent security

Storage

main/speechCloudKeyStore.js follows the keytar-first pattern with service LyricDisplaySpeechCloudKeys and one account per provider: openai or openrouter. When keytar is unavailable, each provider gets its own AES-256-GCM ciphertext and 0600 random key file. Clear removes only that provider's stores, so the other key survives.

Exposure

IPC answers only { ok, configured, provider }. The renderer never reads the key back, no key text enters localStorage, and the fork receives it only through LD_SPEECH_CLOUD_KEY in the child environment. Logs, health payloads, and error messages carry no key, audio, provider body, or transcript.

Consent is an explicit checkbox in Settings → Speech & AI → Cloud: “I understand audio leaves this computer.” Main keeps it in memory for the session, refuses the first cloud start until it is ticked, and revokes it when leaving Cloud, switching provider, resetting, or restarting. Test Mode plus Cloud is refused rather than allowing canned text to wear a cloud label.

10 / Runbook
  1. Configure in the app. Open User Preferences → Experimental → Speech & AI → Cloud. Select OpenAI or OpenRouter · Google Gemini, choose the model, paste that provider's key into its password field, click Save key, and confirm the status reads “Key saved in secure storage.” Keys are stored separately.
  2. Grant egress. Tick “I understand audio leaves this computer,” keep Engine Mode on Production, and arm Sermon Assist. Cloud + Test Mode refuses by design.
  3. Configure the engine directly. Set LD_SPEECH_CLOUD_PROVIDER=openai or openrouter, set the matching LD_SPEECH_CLOUD_KEY, and optionally set LD_SPEECH_CLOUD_MODEL (whisper-1 or google/gemini-2.5-flash). Then run node speech-engine/index.js --engine=cloud. A missing key, provider, or bad model exits 2.
  4. Test locally. Run node --test speech-engine/, then npx vitest run tests/speech src/speech src/components/Speech. No key and no network are needed.
  5. Clear the key. Click Clear key for the selected provider. Only that lane's key is deleted; the other status badge is unaffected.
  6. Watch. Check the rail for speech:error codes, the mode indicator (“Cloud · openai” or “Cloud · openrouter”), health backend: cloud-openai / cloud-openrouter, and the per-provider key status badge. Treat rate-limit and auth codes as operator actions; never paste a key into logs or tickets.
