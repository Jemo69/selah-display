Technical system report

Speech network architecture

Local-network remote engine transport for Selah Live Sermon Assist. This report describes the behaviour of PR #81, commit bb35c5e5 plus the documentation commit on the same bookmark.

Branch: feat/speech-network-remote Protocol: v1 Posture: trusted LAN No TLS

01 · Outcome

Network mode now talks to a real speech engine on another machine: the app validates a configured http(s) endpoint and a session-only token, performs a tokened GET /v1/health with a bounded timeout and protocol check, then hands the renderer the same { endpoint, token, path } dial-in block a local engine start returns so it can open ws(s)://<host>/v1/stream?token=… and stream raw PCM frames. Contract-valid transcript messages from that remote socket are relayed into the existing rail runtime. No local engine is forked in network mode, no local engine is used as a fallback, and a failed start clears health so the interface never claims “Remote engine” without evidence.

02 · Architecture

Health and token travel from main to the remote engine first. Only after that probe succeeds does the renderer dial the remote WebSocket; the engine opens its session on the upgrade and returns validated messages. The app-side transcript-history recorder remains local-only in this branch — network mode relays live rail messages, it does not attach the main-process history store.

03 · Ins and outs

StageInOut
Input
Endpoint validation		 networkEndpoint from settings (or registered default). Origin-only http(s) URL with no credentials, wildcard host, path, query, or fragment. LAN hosts are accepted because choosing Network Device is the explicit operator opt-in.
Input
Token validation		 networkToken from session memory. Non-empty string, 16–256 characters. Never persisted to localStorage; a reload asks again.
Probe
Health check		 Validated endpoint + token. GET <endpoint>/v1/health with x-ld-speech-token, 5 s timeout, v1 compatibility check. Returns renderer-shaped health with remote: true and status: 'ok'.
Dial
Session		 { endpoint, token, path: '/v1/stream', remote: true }. The renderer dials ws(s)://…/v1/stream?token=…. The engine opens its own session on upgrade and emits a ready message. No local supervisor session is created.
Audio
PCM frames		 16 kHz mono, Int16 little-endian, 100 ms / 3200-byte frames. Frames are sent binary, back to back, with a bounded 300-frame drop-oldest queue while the socket opens. Audio crosses the LAN in cleartext.
Output
Transcript relay		 JSON messages on the remote socket. Every message is schema-validated; partial, final, vad, and error are fanned out to the existing rail runtime. Invalid messages are dropped and counted.
Stop
Teardown		 speech:stop. Closes the renderer socket, clears queued audio and remote health, and reports stopped:false, remote:true. It never kills a remote process and never calls the local supervisor kill path for a remote-only session.
Guard
No local fork		 where === 'network'. The remote branch returns before every local provider/binary/model gate. If a local engine was running from an earlier local session, a successful switch stops it; it never starts one.

04 · Security model

  • Local default. The engine binds 127.0.0.1 unless the operator explicitly sets --allow-lan or LD_SPEECH_ALLOW_LAN=1. A non-loopback host without the opt-in throws at construction and at listen(). The opt-in prints an auditable LAN OPT-IN line naming the host, never the token.
  • Token requirement. The opt-in requires an explicit token of at least 16 characters, supplied by --token or LD_SPEECH_TOKEN. There is no generated-token fallback for a LAN bind; the entry point exits 2 without one. The same token gates REST (x-ld-speech-token) and the WebSocket upgrade (?token=…) with a timing-safe compare.
  • Origin / CORS posture. By default the engine accepts only the pinned loopback dev origins (or any loopback http(s) origin from the packaged app), and refuses any other Origin before the token check. A CORS preflight is origin-checked but token-less by browser design. The LAN opt-in widens this to any http(s) Origin and permits non-loopback peers; the token gate remains. Requests with no Origin are still allowed as non-browser clients, gated by the token.
  • No TLS. Transport is plain HTTP and ws:// on a trusted LAN. Raw PCM audio crosses the network, and the shared token appears in the WebSocket query string. The token is an access gate, not encryption.
  • Trusted-LAN assumption. Only run the engine on a network you control. The application refuses to dial a LAN endpoint unless main returned remote: true from a health-checked network start and the caller asked for where: 'network'; local mode keeps its loopback-only dial gate.
  • Hostile LAN peer. A peer on the same untrusted segment can passively observe sermon audio and the token in cleartext, replay the token to open its own REST/WS session, inject forged transcript messages into a connected renderer, or deny service by flooding/refusing connections. This is why the opt-in is explicit and why the UI warns that audio leaves the machine. The design does not claim confidentiality or peer authentication beyond possession of the shared token.
Hard constraint: trusted LAN only. No TLS exists in this architecture. Do not expose the engine port to a public or shared network.

Related gates outside the main refusal table

  • Engine REST/WS: origin-not-allowed, non-loopback-peer, missing-token, invalid-token. Bind refusal without opt-in is a construction/listen error; opt-in without a token exits 2.
  • Renderer dial guards: invalid-endpoint, non-loopback-endpoint, missing-token, missing-path, websocket-unavailable, dial-failed. No socket is created for these.
  • Cloud mode: still where-not-implemented; it has no transport and never uses the network path.

07 · Setup ownership and lab verification

Product rule: all Sermon Assist setup is owned by the Selah desktop app and lives in this repository. No external plugins, sidecar repos, separate installer projects, or zip bundles of loose executables. The app probes the machine, verifies downloads, installs engine and model, selects them, and explains every step in plain language. A volunteer is never asked to locate, copy, configure, or run a file by hand.

This PR implements the transport contract only. The one-click, app-owned provisioning of a remote engine is required product work and is not delegated outside the app repo. The commands below are developer lab verification only: they exist to exercise the LAN opt-in gate in a test harness. They are not an operator setup path and must not be shipped as one.

Lab verification only — engine host

# Explicit token + explicit LAN opt-in are BOTH required.
# Default port is 4731; use --port or LD_SPEECH_PORT if you change it.
node speech-engine/index.js \
  --host=192.168.1.20 \
  --port=4731 \
  --allow-lan \
  --token=<same-long-token>

# Equivalent environment form:
LD_SPEECH_ALLOW_LAN=1 \
LD_SPEECH_HOST=192.168.1.20 \
LD_SPEECH_PORT=4731 \
LD_SPEECH_TOKEN=<same-long-token> \
node speech-engine/index.js
  • Token must be the same value entered in the app and at least 16 characters. It is never generated for a LAN bind.
  • Allow inbound TCP on the chosen engine port from the app machine. The renderer connects directly to that port over ws://.
  • Expect an LAN OPT-IN warning naming the bind host. A non-loopback bind without the opt-in, or the opt-in without a token, is refused.
  • Run a real recognizer on that machine; the canned fake backend reports itself honestly and will be labelled as canned text in the rail.

In-app transport configuration (this PR)

  1. Open User Preferences → Experimental → Speech & AI, enable Sermon Assist, and choose Network Device.
  2. Enter the engine origin, for example http://192.168.1.20:4731. No path or credentials.
  3. Enter the launch token. It lives only in session memory; a reload asks again. The endpoint is saved.
  4. Press Test connection. Success means the tokened health probe answered; it does not start a session.
  5. Arm an audio source. Only after a successful start does the label read “Remote engine · <model>”; otherwise it reads “Network · not connected”.
  6. Stopping closes the stream and the session view. It does not shut down the remote machine or its engine process.

09 · Not verified

  • No second physical machine was available, so there has been no live two-machine smoke test.
  • Cross-host routing and firewall behaviour on a real church LAN are unverified.
  • Wi-Fi/Ethernet loss and reconnect behaviour during a service are unverified; the transport has no auto-reconnect in this branch.
  • TLS is not implemented and is not verified — by design. The trusted-LAN assumption is a manual operational control.
  • App-owned one-click provisioning of the remote engine is not implemented in this branch; only the transport, validation, and in-app endpoint/token controls are. The required follow-up stays inside src/, main/, shared/, speech-engine/, tests/ and docs/.
